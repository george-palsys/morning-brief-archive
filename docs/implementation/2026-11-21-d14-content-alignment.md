### 5.2 1380px 兩欄門檻取代 250px 目錄的理由與推算依據（推算值，不是官方標準）

以下來自設計規格 1.2 章對 D14 實作的實測與推算。**1380 是推算值**，不是 WCAG 或任何原廠標準的數字。

1. 實測基礎：視窗 921px 時 `.content-inner` 為 672px、正文卡為 330px（headless Chrome、捲軸 15px；若無捲軸則 345px）。
2. 關係式：正文卡寬 ＝ 視窗寬 − 249 − 342。249 為側欄 218＋捲軸 15＋框架 padding 16；342 為目錄 300＋gap 42。此關係成立到 `.content-inner` 達 1144px 上限（視窗約 1393px）。
3. CVE 條目卡內還有 padding 50、CVE rail 240、間距 25，因此 CVE 正文欄 ＝ 視窗寬 − 934。
4. 以「中文正文欄至少 440px（約 27 個全形字）」為下限；這個 440px 是設計規格自訂的最小可讀行寬，**沒有 WCAG 條文**。視窗 ≥1374px 時正文欄 ≥440px，取整為 1380px。
5. 反證：視窗 921 時正文欄約 60px（一字一行），1280 時約 346px，皆不可讀；這是 V1 放棄 250px 右欄、改單欄的實測依據。
6. 實測驗證（v3）：視窗 1380 時 CVE 正文欄為 445.33px（含 15px 捲軸，獨立驗證與設計審查皆量到 445）；無捲軸環境 460px，兩者都 ≥440px，餘裕 5px 以上。視窗 1379 為單欄。
7. 限制：1381–1439 之間的連續變化只測了 1380 與 1440，沒有測中間值；上列公式在 921px 代入會得負值，與實測約 60px 不一致，所以它只用於 1374–1440 範圍的推算，不能外推到窄寬度。

CVE rail 在卡內右側的門檻同理為推算：正文欄 ＝ 視窗寬 − 564，要 ≥440px 需視窗 ≥1004px，取整 1010px；<1010px 時 rail 堆疊在標題下方滿寬（CSS 以 `max-width:1009.98px` 涵蓋分數像素）。實測 1009 堆疊、1010 並排，各寬整頁溢出 0。1009 到 1010 之間 CVE 正文欄由 708 跳到 445（獨立驗證含捲軸量測 708／445；無捲軸量測 723／460），是並排門檻造成的不連續，屬預期。
